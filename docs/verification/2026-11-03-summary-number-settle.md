# 2026-11-03 最终总结数字落定修复

恢复基线 `f39a44b`（build 89），恢复登记 `1ceb945`。用户实机截图显示最终文件总结的红绿数字停在上下两组数字各露一部分的中间帧；截图仅在本机会话中检查，未复制到仓库。

## 原因与修改

旧实现结束时修改 Counter 内存状态，但 TextView 仍持有可变 CountSpan；重绘入口又跳过不可见行。当气泡在滚动中离屏，动画结束不会使该行失效；中途 detach 也只结束计时器，没有把已安装的动态数字替换为静态文字。这使最后可见的中间帧可能被保留，不能依赖后续消息更新或点开气泡纠正。

RollingChangeNumbers 现在提供只转换已结束数字 span 的入口，保留原文、颜色和图标；ToolActivityGroupView 在完成时即使行被裁剪也提交静态文字，detach 后同样归位。仍在运行的离屏帧跳过绘制；同值不重播，队列合并与加减速不变。只更新数字文字，不重新绑定整个气泡或重建展开详情；不改变会话字段、协议、权限、存储格式、依赖或 UI 样式。需求 R-31、验收及架构同步明确最后一帧和 detach 的职责。

## 复现与定向验证

新增 SummaryNumberAnimationTest 在 Android 8／15（API 26／35）下各检查三种情形：没有新会话刷新也落定、滚动离屏时最后一帧请求重绘、首轮动画中移除后重新附着。用实际 ValueAnimator 定位到 100ms 中间帧后，让主线程推进到结束；以视图失效请求、完整静态文字、颜色／图标、原详情对象和原生帧绘制检查结果。

在修复前的生产代码上，这六项均失败：离屏用例没有末帧失效请求，其余用例落定后仍有两个动态数字 span。修复后，同一六项及原数字加速／跨位数检查、Activity 的最终摘要／任务结束／详情不重建回归，共 11 项通过，失败／错误／跳过均为 0。API 26／35 的合成截图位于 `app/build/screenshots/summary-number-settled-api26.png` 和 `summary-number-settled-api35.png`，显示“已更改36个文件 +648 −648”完整落定。

这些检查复现了漏掉末帧更新的客户端路径；Robolectric 的绘制和失效请求不能证明已在用户手机的硬件缓存中复现完全相同的偶发条件。完整验收及安装包交付将在独立版本阶段记录；手机覆盖安装和真实滚动效果仍待测试。
