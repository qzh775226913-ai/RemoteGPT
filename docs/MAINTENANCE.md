## 代码约束

- 新业务放入职责明确的模块；禁止给 `MainActivity` 或 `RemoteApp` 持续追加完整功能流程。
- 模块登记覆盖全部主 Java 文件。默认文件预算 450 行；现有大入口采用整理后的上限。超过上限必须先做有意义的职责拆分，不以移除空行／注释或提高数字应付检查。
- 控制器保持包内可见，UI 不直接管理 Socket、原始 RPC 或执行 worker 里的 View 更新。
- 只在 `ConversationStore` 执行背景会话切换；统一请求路由保存发起会话与连接 generation。并行状态变更必须测试异常、迟到回调和历史重放。
- 格式、协议／数据迁移、功能修改和依赖升级分别提交；保持旧数据兼容，不用“重构”顺便改掉用户已确认的菜单。
- 不删除真机待验项目，不把 UNKNOWN 显示为成功或额度 100%，不把 mock/backend 测试说成真实模型验收。

## 仍需逐步消化的技术债

| 优先级 | 项目 | 当前保护与后续做法 |
| --- | --- | --- |
| 高 | `RemoteApp` 的选中状态与 `ConversationState` 双份字段 | 已集中分发、异常恢复和主线程校验；下一阶段让控制器接收明确状态对象，再迁移 UI 到只读快照。每批需 A/B、审批、草稿、重放回归，不一次替换所有公共字段 |
| 高 | 连接恢复、快照合并和事件处理仍集中在 `RemoteApp` | 保留统一时序；下一步分别拆恢复协调器、线程快照合并器。保持快照先应用、事件后发布及旧托管兼容 |
| 中 | 消息／媒体视图协调仍部分在 `MainActivity` | 已拆表单、模型窗口与 `MessageImageTile` 可见图片生命周期；后续拆带生命周期的消息列表组件，保持旧消息阅读冻结和缩略图释放 |
| 中 | 多个现有测试通过反射注入 RPC／调用事件 | 此轮缓存测试改为使用类型明确的容器；逐步提供包内测试边界，保留外部行为断言，不能为了测试把内部全部公开 |
| 中 | 原代码部分压缩排版、同包平铺 | 新模块明确职责并登记；格式整理单独进行，避免大面积机械差异盖住状态改动 |
| 中 | AGP/compileSdk 提示及既有 Lint 警告 | 日期报告记录；另开工具链／国际化变更，不静默抑制 |
| 持续 | 真机、真实 Codex、tailnet 和覆盖安装证据不足 | 保留待验清单；取得指定版本／设备证据后再更新支持范围 |

不能把以上债务写成已完成，也不需要为了本轮整理额外引入 MVVM 框架、数据库迁移或一套新的 UI 技术。
